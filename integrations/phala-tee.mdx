In production, every Delibera agent runs inside a [Phala Network](https://phala.network/) Confidential Virtual Machine (CVM). Phala's TEE guarantees that agent code cannot be tampered with after deployment — not by the operator, not by the infrastructure provider.

## How TEE deployment works

<CardGroup cols={2}>
  <Card title="Confidential VM" icon="shield">
    Each agent runs in a hardware-isolated CVM backed by Intel TDX. Code and memory are encrypted; even the host cannot inspect the running process.
  </Card>
  <Card title="Shade Agent v2" icon="code">
    Agents initialize via the NEAR Shade Agent v2 pattern: the CVM derives a NEAR key on first boot and registers itself on-chain.
  </Card>
  <Card title="Codehash registration" icon="fingerprint">

  </Card>

## LOCAL_MODE

The `LOCAL_MODE` environment variable switches agents between local development and production TEE mode:

| Value | Behavior |
|-------|----------|
| `true` | Skip Shade Agent initialization. Use local NEAR key from `NEAR_SEED_PHRASE`. No CVM required. |
| `false` | Run full Shade Agent v2 initialization. Requires Phala CVM environment with dstack socket. |

```bash
# Local development
LOCAL_MODE=true

# Production (Phala TEE)
LOCAL_MODE=false
```

<Warning>
Never set `LOCAL_MODE=true` in production. Without TEE initialization, the agent's NEAR key is not attested to hardware, and the system's trust guarantees do not hold.
</Warning>

## Shade Agent v2 initialization

Shade Agent v2 provides the NEAR SDK integration for TEE-hosted agents. On first boot inside a Phala CVM, the agent:

1. Derives a fresh Ed25519 NEAR keypair from the CVM's hardware entropy
2. Registers the public key with the sponsor account on NEAR
3. Receives a function-call access key scoped to the coordinator contract
4. Begins normal operation

This flow requires the following environment variables in production:

```bash
AGENT_CONTRACT_ID=coordinator.agents-coordinator.testnet
SPONSOR_ACCOUNT_ID=agents-coordinator.testnet
SPONSOR_PRIVATE_KEY=ed25519:your-sponsor-key
NEAR_NETWORK=testnet
LOCAL_MODE=false
```

For full Shade Agent documentation, see the [NEAR Shade Agents guide](https://docs.near.org/ai/shade-agents/getting-started/introduction).

## Codehash registration

Before an agent CVM can interact with the coordinator contract, its Docker image codehash must be approved. The codehash is the SHA-256 hash of the container image, deterministically computed at build time.

The `API_CODEHASH` in `.env.example` corresponds to the approved coordinator agent codehash:

```bash
API_CODEHASH=a86e3a4300b069c08d629a38d61a3d780f7992eaf36aa505e4527e466553e2e5
```

Approve a codehash on the coordinator contract:

```bash
near call coordinator.agents-coordinator.testnet approve_codehash \
  '{"codehash": "a86e3a4300b069c08d629a38d61a3d780f7992eaf36aa505e4527e466553e2e5"}' \
  --accountId agents-coordinator.testnet \
  --networkId testnet
```

Only the contract owner (`agents-coordinator.testnet`) can approve codehashes.

## CVM registration

After a CVM boots and initializes as a Shade Agent, its CVM ID is stored in the registry contract. This makes the entire agent fleet auditable:

```bash
near view registry.agents-coordinator.testnet list_active_coordinators \
  --networkId testnet
# Returns: [{ endpoint, cvm_id, ... }]
```

CVM IDs are also mirrored in Ensue memory under `coordination/agents/{agentId}/cvm_id` for fast runtime lookup.

## Docker setup

The `docker-compose.yaml` mounts the dstack socket, which is required for CVM attestation:

```yaml
services:
  coordinator-agent:
    image: ${DOCKER_TAG}
    platform: linux/amd64
    restart: always
    ports:
      - "3000:3000"
    volumes:
      - /var/run/dstack.sock:/var/run/dstack.sock  # Required for Phala TEE
    environment:
      LOCAL_MODE: "false"
      AGENT_CONTRACT_ID: ${AGENT_CONTRACT_ID}
      SPONSOR_ACCOUNT_ID: ${SPONSOR_ACCOUNT_ID}
      SPONSOR_PRIVATE_KEY: ${SPONSOR_PRIVATE_KEY}
      NEAR_NETWORK: ${NEAR_NETWORK}
      ENSUE_API_KEY: ${ENSUE_API_KEY}
```

The dstack socket provides the CVM's hardware attestation interface. Without it, Shade Agent v2 cannot derive a trusted keypair.

## What LOCAL_MODE=false enables

When running in a Phala TEE with `LOCAL_MODE=false`:

- The agent's NEAR key is derived from hardware entropy — no human ever sees it
- NEAR AI verification proofs link agent votes to this TEE-attested key
- The coordinator contract can verify the agent's identity via the approved codehash
- On-chain records tie CVM IDs to agent registrations in the registry contract
