The FHE voting contract is Delibera's V2 feature for high-stakes proposals that require maximum vote secrecy. It runs on a Zama fhEVM chain and uses Fully Homomorphic Encryption (FHE) to accumulate vote tallies without ever revealing individual ballots — even to the smart contract itself.

**Contract:** `contracts/voting/contracts/DeliberaVoting.sol`

## How FHE voting works

In standard Ethereum smart contracts, storing a vote accumulator as a plaintext integer exposes the running tally to everyone. Zama fhEVM solves this by running the EVM with FHE support, where `euint32` values are ciphertexts that can be operated on arithmetically without decryption.

The voting flow:

```
Voter encrypts ballot locally (0 = Rejected, 1 = Approved)
       ↓
castVote() → FHE.add(encryptedApproved, vote)
                FHE.add(encryptedRejected, 1 - vote)
       ↓
[deadline passes]
       ↓
finalize() — TEE only, marks proposal as finalized
       ↓
TEE decrypts encryptedApproved and encryptedRejected locally
       ↓
publishResult() — TEE writes plaintext counts on-chain
       ↓
ResultPublished event emitted with approved, rejected, decision
```

At no point is the intermediate tally visible on-chain. Even a blockchain explorer cannot determine how many votes have been cast for each option until `publishResult` is called.

## Relationship with the coordinator contract

The FHE voting contract is an **optional** parallel track. For most proposals, Delibera uses the primary coordinator contract on NEAR (the yield/resume pattern with off-chain Ensue privacy). For high-stakes proposals where on-chain cryptographic privacy is required, you deploy the FHE voting contract on a Zama fhEVM chain and route voter agents to `castVote()` instead.

The coordinator agent on NEAR is responsible for bridging the final result: after `publishResult()` emits the plaintext counts, the coordinator reads them and settles the aggregate on the NEAR coordinator contract.

## Contract methods

### constructor

Deploys the contract and sets the owner and TEE address.

<ParamField body="_teeAddress" type="address" required>
  Ethereum address of the Phala TEE that is authorised to call `finalize()` and `publishResult()`.
</ParamField>

```solidity
new DeliberaVoting(0xTEE_ADDRESS);
```

---

### createProposal

Creates a new proposal for blind voting. Owner only.

<ParamField body="description" type="string" required>
  The proposal text.
</ParamField>

<ParamField body="duration" type="uint256" required>
  Voting duration in seconds. The deadline is `block.timestamp + duration`.
</ParamField>

Returns the `proposalId` (incrementing integer starting at 0).

```solidity
uint256 proposalId = deliberaVoting.createProposal(
    "Fund a developer grant program for 10,000 NEAR",
    7 days
);
```

---

### castVote

Casts an FHE-encrypted vote. Any address may call this while the proposal is open and not yet finalised.

<ParamField body="proposalId" type="uint256" required>
  The proposal to vote on.
</ParamField>

<ParamField body="encryptedVote" type="externalEuint32" required>
  An FHE-encrypted `uint32`. Encrypt `1` for `Approved` or `0` for `Rejected` using the Zama fhEVM client library.
</ParamField>

<ParamField body="inputProof" type="bytes" required>
  The proof accompanying the encrypted input, generated by the fhEVM client when encrypting the vote.
</ParamField>

```solidity
// Using the Zama fhEVM client (JavaScript)
import { createInstance } from 'fhevmjs';

const instance = await createInstance({ network: window.ethereum });
const { handles, inputProof } = await instance
  .createEncryptedInput(CONTRACT_ADDRESS, signerAddress)
  .add32(1)  // 1 = Approved, 0 = Rejected
  .encrypt();

await deliberaVoting.castVote(proposalId, handles[0], inputProof);
```

<Note>
The contract accumulates `approved` with `FHE.add(encryptedApproved, vote)` and `rejected` with `FHE.add(encryptedRejected, FHE.sub(1, vote))`. Each voter contributes exactly 1 vote split between the two tallies.
</Note>

---

### finalize

Marks the proposal as finalised. Can only be called by the TEE address after the voting deadline has passed.

<ParamField body="proposalId" type="uint256" required>
  The proposal to finalise.
</ParamField>

```solidity
// Called by the Phala TEE coordinator
await deliberaVoting.finalize(proposalId);
```

After this call, no more votes can be cast. The TEE can then decrypt the encrypted tallies locally (it has FHE access granted via `FHE.allow`) and prepare the plaintext results for `publishResult`.

<Warning>
Only the `teeAddress` can call `finalize()`. If the TEE is unavailable, the proposal will remain in the `finalized=false` state indefinitely. Rotate the TEE address via `setTeeAddress()` if the original TEE is compromised.
</Warning>

---

### publishResult

Publishes the decrypted vote counts on-chain. Can only be called by the TEE address after `finalize()`. Can only be called once per proposal.

<ParamField body="proposalId" type="uint256" required>
  The proposal ID.
</ParamField>

<ParamField body="approved" type="uint32" required>
  The decrypted count of approved votes.
</ParamField>

<ParamField body="rejected" type="uint32" required>
  The decrypted count of rejected votes.
</ParamField>

```solidity
// Called by the Phala TEE after decrypting the FHE tallies
await deliberaVoting.publishResult(proposalId, approved, rejected);
```

The contract determines the decision as `"Approved"` if `approved >= rejected`, otherwise `"Rejected"`, and emits `ResultPublished(proposalId, approved, rejected, decision)`.

---

### getProposal

View function. Returns public proposal metadata. Does not expose the encrypted tallies.

<ParamField body="proposalId" type="uint256" required>
  The proposal ID.
</ParamField>

Returns: `(description, deadline, voteCount, finalized, resultApproved, resultRejected)`.

```solidity
(string memory description, uint256 deadline, uint32 voteCount,
 bool finalized, uint32 resultApproved, uint32 resultRejected)
  = deliberaVoting.getProposal(proposalId);
```

`resultApproved` and `resultRejected` are `0` until `publishResult` is called.

---

### getEncryptedApproved / getEncryptedRejected

View functions. Return the raw `euint32` ciphertext for the approved and rejected tallies. Only addresses that have been granted FHE access (the contract itself, `owner`, and `teeAddress`) can meaningfully use these values.

```solidity
euint32 encApproved = deliberaVoting.getEncryptedApproved(proposalId);
```

---

### hasVoted

View function. Returns whether an address has already voted on a proposal.

<ParamField body="proposalId" type="uint256" required>
  The proposal ID.
</ParamField>

<ParamField body="voter" type="address" required>
  The voter's address.
</ParamField>

```solidity
bool voted = deliberaVoting.hasVoted(proposalId, voterAddress);
```

---

### setTeeAddress

Updates the TEE address. Owner only. Use this to rotate the TEE key if the original Phala CVM is replaced.

<ParamField body="_teeAddress" type="address" required>
  The new TEE Ethereum address.
</ParamField>

```solidity
await deliberaVoting.setTeeAddress(newTeeAddress);
```

## Events

| Event | Parameters | Description |
|-------|------------|-------------|
| `ProposalCreated` | `proposalId, description, deadline` | Emitted when a new proposal is created. |
| `VoteCast` | `proposalId, voter` | Emitted for each successful vote. Does not include the vote value. |
| `ProposalFinalized` | `proposalId` | Emitted when the TEE marks the proposal finalised. |
| `ResultPublished` | `proposalId, approved, rejected, decision` | Emitted when the TEE publishes the plaintext result. |

## FHE access control

The contract grants FHE decryption access to three parties for each encrypted tally value:

- **The contract itself** (`FHE.allowThis`) — for on-chain accumulation.
- **The owner** (`FHE.allow(encryptedApproved, owner)`) — for governance oversight.
- **The TEE** (`FHE.allow(encryptedApproved, teeAddress)`) — for decryption and result publication.

No other address can decrypt the tallies, even if they can see the ciphertext bytes on-chain.

<Tip>
Zama fhEVM uses a threshold decryption network (the Zama KMS) to handle key management. The `teeAddress` acts as the gateway: it requests decryption from the KMS inside the TEE enclave, where the plaintext result is never exposed outside the hardware boundary.
</Tip>
